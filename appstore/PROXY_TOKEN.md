# プロキシの保護（回数制限と認証トークンの切り替え）

アプリが判定のために呼ぶサーバー（プロキシ）を、不正利用から守るための変更と、その手順です。

- 何をしたか: プロキシに回数制限を入れ、認証トークン（合言葉）を新しくして、Git に入れない形に変えました。
- **あなたの作業が1つ必要です。** 新しいトークンを Cloud Run に登録すること（2章）。これをしないと、次のバージョンのアプリは判定できません。

## 1. いまの状態

| アプリのバージョン | 使うトークン | 判定できる条件 |
|---|---|---|
| 公開中の 1.x、審査に出した 2.0 | 古いトークン（GitHub の履歴で公開されている） | Cloud Run の `SECRET_TOKEN` が今のままなら動く |
| これからビルドするもの（次のバージョン） | 新しいトークン（この Mac の `myakuari/Secrets.swift` にだけある） | Cloud Run の `SECRET_TOKENS` に新しいトークンを登録してから |

**注意: 2.0 が審査で差し戻され、いまのコードからビルドし直す場合も、新しいトークンが使われます。先に2章を済ませてください。**

プロキシは、古いトークンと新しいトークンの両方を受け付けるようにしてあります。古いバージョンを止めずに切り替えられます。

## 2. Cloud Run に新しいトークンを登録する（必須）

1. この Mac で `myakuari/Secrets.swift` を開き、`apiAuthorizationKey` の値（英数字48文字）をコピーする。
2. Google Cloud コンソール → Cloud Run → サービス `gemini-api-key-proxy` を開く。
3. 「新しいリビジョンの編集とデプロイ」→「変数とシークレット」を開く。
4. 環境変数を追加する。
   - 名前: `SECRET_TOKENS`
   - 値: 手順1でコピーした値
5. **`SECRET_TOKEN`（末尾に S がない方）は消さずに残す。** 公開中のアプリがこれを使っています。
6. 「デプロイ」を押す。

登録が終わったら知らせてください。新しいトークンで本番のプロキシを呼び、通ることをこちらで確認します。

`SECRET_TOKENS` はカンマ区切りで複数のトークンを入れられます。次にトークンを変えるときは、新しい値を後ろに足します。

## 3. 古いトークンを止める（あとで）

古いトークンは GitHub の履歴に残っているので、誰でも読めます。止めるまでは回数制限（4章）が歯止めになります。

止める時期の目安は、新しいトークンを使うバージョンが公開されてから数週間後、古いバージョンの利用がほぼなくなったときです。

1. Cloud Run の環境変数から `SECRET_TOKEN` を削除してデプロイする。
2. この時点で、古いバージョンのアプリ（1.x と 2.0）は判定できなくなります。画面には「ただいまAI判定サーバーに接続できません。回数は減っていません。」と表示され、回数は減りません。

古いバージョンを使っている人がどれくらいいるかは、App Store Connect →「App アナリティクス」→ バージョン別のアクティブデバイスで確認できます。

## 4. 回数制限の内容

認証を通ったリクエストを、接続元の IP アドレスごとに数えます。超えると HTTP 429 を返し、アプリは「ただいまアクセスが集中しています。回数は減っていません。」と表示します。

| 制限 | 既定値 | 環境変数 |
|---|---|---|
| 1つの IP から10分あたり | 20回 | `RATE_LIMIT_PER_10MIN` |
| 1つの IP から24時間あたり | 100回 | `RATE_LIMIT_PER_DAY` |
| 全体で24時間あたり | 5000回 | `GLOBAL_DAILY_LIMIT` |

- 値は Cloud Run の環境変数で変えられます。`0` にするとその制限は無効になります。
- ふつうの使い方（1日に数回）では当たらない値にしてあります。携帯回線では複数の人が同じ IP を共有することがあるので、IP ごとの制限は緩めです。
- 「全体で24時間あたり」は課金の上限ガードです。利用者が増えて1日5000回に近づいたら、値を上げてください。上限に達すると、全員が24時間以内の古い分が消えるまで判定できなくなります。
- カウントはサーバーのメモリ上にあります。Cloud Run がインスタンスを増やしたり再起動したりすると、インスタンスごとに別々に数えられ、再起動で 0 に戻ります。厳密な上限ではなく、大量の不正利用を止めるための歯止めです。
- 1回のリクエストは 8MB までに制限しました。

設定の確認用に `GET /whoami` を追加しています。認証トークンを付けて呼ぶと、制限に使われる IP と現在の制限値が返ります。

## 5. アプリ側の変更

- トークンを `Info.plist` から削除し、`myakuari/Secrets.swift` に移しました。このファイルは `.gitignore` に入れてあり、Git にも GitHub にも入りません。
- トークンを新しい値に変えました。
- プロキシが 429 を返したときの案内文を4言語で追加しました。

アプリに入れたトークンは、Git に入れなくても、アプリ本体を解析すれば取り出せます。トークンは「通りすがりの不正利用を防ぐもの」で、実際に利用量を抑えるのは回数制限です。

## 6. 別の Mac でビルドするとき

`myakuari/Secrets.swift` は Git に入っていないので、リポジトリを取得し直した直後はビルドが失敗します（`Cannot find 'Secrets' in scope`）。

1. `Config/Secrets.swift.example` を `myakuari/Secrets.swift` としてコピーする。
2. `apiAuthorizationKey` に、Cloud Run の `SECRET_TOKENS` に登録してあるトークンを入れる。

**`myakuari/Secrets.swift` をなくすと、同じトークンは復元できません。** その場合は新しいトークンを作り（`openssl rand -hex 24`）、Cloud Run の `SECRET_TOKENS` にカンマ区切りで追加してください。パスワード管理アプリなどに控えておくことを勧めます。

## 7. 予算アラート

回数制限とは別に、Google Cloud 側で課金の通知を設定しておくと安心です。

1. Google Cloud コンソール →「お支払い」→「予算とアラート」→「予算を作成」。
2. 対象のプロジェクトを選び、月の予算額（例: 普段の利用額の2〜3倍）を入れる。
3. 50%・90%・100% でメール通知する設定にする。

予算アラートは通知だけで、利用は止まりません。止めるのは4章の回数制限です。
